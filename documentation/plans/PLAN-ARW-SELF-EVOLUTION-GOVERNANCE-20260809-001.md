# Objective

Prove proposal-first governance for durable self-evolution from real repeated/material evidence, without duplicating ordinary system-change execution owned by #15.

# Activation gate

Require a real candidate supported by repeated observations or a clearly high-impact failure from prior executed work. Synthetic examples may test formatting but cannot satisfy the pilot.

# Execution phases

1. Collect the candidate evidence and provenance.
2. Test recurrence/materiality and whether the problem is already solved locally.
3. Classify the proposed outcome: policy, skill, workflow, script, routing, project-local, no-change, or defer.
4. Prefer project/local adoption before global promotion where reuse is unproven.
5. Review expected value, maintenance burden, risks, and reversibility.
6. If accepted, hand implementation to the normal #15/general change workflow.
7. Revalidate in real use and record whether the promoted behavior improved the original pattern.

# Validation

- no single low-impact anecdote silently becomes policy;
- evidence and rationale are traceable;
- `NO CHANGE` and `DEFER` are valid outcomes;
- accepted mutation has review and rollback where practical;
- implementation ownership stays with #15/general workflow.

# Stop conditions

Stop/defer if recurrence is weak, project-local handling is sufficient, benefit is speculative, or promotion would create disproportionate global complexity.

# Definition of done

One real candidate is processed end-to-end through evidence check, proposal, review, acceptance/rejection, and handoff/revalidation without automatic self-modification.
