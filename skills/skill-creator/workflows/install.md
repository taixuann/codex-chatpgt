# INSTALL

Use INSTALL only when a maintained, independently installable skill already provides the requested capability and is absent from the chosen target. A maintained existing skill already installed but needing behavior changes routes to UPDATE. Donor/reference-only material routes to CREATE; a material redesign routes to CREATE or UPDATE. Never adapt an installable owner under CREATE merely to avoid INSTALL. EVALUATE is shared evidence, not a peer action.

Read `references/source-strategy.md`, `references/discovery.md`, `references/validation.md`, `references/evaluation.md`, `references/test-environment.md`, `references/provenance.md`, and `references/qualification.md` as their decisions become relevant. Keep generic evaluation separate from the skill-creator self-evaluation corpus.

## Normal path

1. **Resolve and pin the source.** Record the user’s requested repository, ref, and subpath. Inspect current source identity and availability; resolve a branch or tag to an immutable commit before relying on it. Verify provenance and license for the selected package. If identity, terms, or integrity are unresolved, stop before installation and report BLOCKED.
2. **Select the installable package.** Inspect the source tree and package manifest, then identify the smallest complete subtree actually consumed at runtime (the package closure): entrypoint, referenced files, scripts/assets, declared dependencies, and metadata required by the target runtime. Verify links and that required files are included. Exclude tests, CI, build metadata, and unrelated repository files unless the runtime demonstrably consumes them. Record source tree and selected-payload fingerprints.
3. **Choose target and install mode.** Determine target runtime, project/global scope, path, and supported mode (copy, editable checkout, or runtime-native install). Prefer project scope for project-specific evidence; use global scope only when the user intends reusable cross-project behavior. Identify the maintained platform installer/backend that owns placement, updates, uninstall, and ownership. If none exists, first test whether a smaller maintained backend works; add only a bounded adapter when required semantics cannot otherwise be met. Do not reproduce a backend’s mechanics in this workflow.
4. **Check ownership and collisions before mutation.** Inspect the exact destination, runtime discovery order, shadowing siblings, and neighboring canaries. An occupied path without a matching ownership receipt is unmanaged: preserve it and return BLOCKED. Reinstallation or replacement is allowed only when a valid receipt proves ownership and the current payload still matches the recorded installed hash. INSTALL does not perform UPDATE, overwrite unmanaged files, or silently switch scope/mode.
5. **Allocate an isolated trial and baseline.** Follow `references/test-environment.md`: `ALLOCATE → PREPARE → BASELINE → RUN → FREEZE → REPORT → ARCHIVE → CLEAN`. Select a temporary copy for ordinary package/install validation, a worktree when repository Git state or scripts need isolation, and a sandbox when execution risk or filesystem/network boundaries require it. Give each attempt a fresh trial ID; bind candidate/source revision, source/selected payload hashes, test-case fingerprint, target runtime/scope/mode, and baseline identity. Capture target and canary state before installation. If a baseline is inapplicable, record why rather than omit the field.
6. **Install faithfully.** Invoke the selected maintained backend only against the isolated target. Zero adaptation is the default. Compatibility-only changes are permitted only when necessary for the target runtime; enumerate each changed file with source and installed SHA-256 plus a reason of at least one substantive sentence. Every installed file not listed as adapted must match its source snapshot exactly. If requested functionality needs action/workflow redesign or material behavior changes, make no target mutation and route to CREATE or UPDATE with the reason.
7. **Verify the installed result.** Recompute raw SHA-256 for every selected regular file. Define each tree fingerprint as SHA-256 of compact UTF-8 JSON encoding of sorted `[relative POSIX path, lowercase raw-file SHA-256]` pairs with no insignificant spaces. `source_sha256` covers the inspected source package tree, `selected_sha256` covers exactly the selected package closure, and `installed_sha256` covers those same relative paths at the target. When adaptation is `none`, require selected and installed fingerprints and every per-file hash to match. If adaptation occurred, require per-file source/installed hashes to match snapshot contents, a reason, and an explicit bounded compatibility difference. Run deterministic package, path, link, dependency, and runtime validation. Perform a static semantic walkthrough of the actual consumed instructions and confirm they still serve the requested behavior. Run one representative real task through the installed target and inspect its result. Confirm the target is discoverable/loaded where the runtime exposes that evidence; discovery, activation, and successful task behavior are distinct claims. Re-snapshot the target and canaries and reject unexpected writes or shadowing.
8. **Write provenance and ownership evidence.** Record source repository/ref/immutable revision/subpath/license; source tree, selected payload, installed payload and exactly one source/installed hash pair for every selected relative path; installable subtree rationale; target runtime/scope/path/mode; backend and version; adaptation diff or `none`; collision and baseline results; validation commands/results; real-task input/result; activation evidence or `NOT_ASSESSED`; created paths; receipt ID; and a safe uninstall procedure limited to receipt-owned, unchanged files. This install receipt is mandatory: a plan or backend success message alone is not evidence.
9. **Freeze, report, archive, clean.** Freeze evidence before reporting. Report `INSTALLED` only when source, payload, ownership, validation, and real-task evidence pass; otherwise use `BLOCKED` or `PASS_WITH_LIMITATION` with explicit unresolved evidence. Preserve the frozen report and archive identity, then clean temporary roots and record terminal state `CLEANED`, `PRESERVED_FOR_REVIEW`, or `CLEANUP_BLOCKED`. Never erase user/global installs as test cleanup. Qualification remains `fresh WORK → fresh separate GOAL → TECHNICALLY_ELIGIBLE → awaiting_parent_decision`; the parent/human owns acceptance and publication.

## Required outcomes

- **INSTALLED:** faithful install is owned by the selected backend; receipt and evidence bind the exact source and installed payload.
- **BLOCKED:** source/license/integrity, target ownership, backend, validation, or cleanup safety is unresolved; preserve existing state and name the blocker.
- **ROUTE CREATE / UPDATE:** the target needs material design or behavior change; do not mutate it as part of INSTALL.
- **PASS_WITH_LIMITATION:** bounded install evidence passes but a distinct claim such as activation or visual inspection is unavailable; name it `NOT_ASSESSED` and do not imply qualification.
