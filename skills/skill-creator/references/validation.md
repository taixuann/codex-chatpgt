# Validation

Owner: deterministic/mechanical validation. Consumers: CREATE/UPDATE U7/U8 and package qualification. Persistence: scripts and compact result pointers. Non-overlap: evaluation owns real-task behavior; review owns semantic challenge.

Check frontmatter/name/path, relative links, package closure, orphan/stale resources, script syntax/execution, eval schema, runtime metadata only when a consumer exists, dependency availability, and approved architecture conformance. Validate changed and protected contracts separately.

Use PASS, FAIL, and NOT_ASSESSED honestly. Bind results to the exact candidate/base where the contract is revision-sensitive. A green check cannot prove runtime activation, independent review, or scientific acceptance.
