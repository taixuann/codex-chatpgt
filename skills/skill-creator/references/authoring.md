# Authoring

Owner: bounded package writing and allocation. Consumers: CREATE/UPDATE build and mutation phases. Persistence: runtime package files only when consumed. Non-overlap: architecture decides responsibility; validation checks mechanics.

Keep SKILL.md as a discriminating router, route substantial conditional detail progressively, put normal path before edge cases, and give every workflow/reference/script a consumer. Prefer deletion or navigation over duplicate rules. Keep runtime instructions separate from intent, traces, baselines, and reports.

Before mutation, map each file to behavior, source, consumer, validation, lifetime, and runtime/creation-only status. Do not add placeholders, UI metadata, assets, or abstractions without a demonstrated consumer.
