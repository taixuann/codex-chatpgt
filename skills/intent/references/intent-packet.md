# Intent packet contract

Minimal YAML shape:

```yaml
schema_version: 1
kind: intent_packet
source:
  kind: user                 # user | github_issue
  locator: conversation
objective: "..."
why: "..."
success_criteria:
  - "..."
scope:
  - "..."
out_of_scope:
  - "..."
assumptions: []
open_questions: []
decisions: []
unknowns: []
evidence:
  - id: E1
    locator: AGENTS.md
    kind: repository
    observed_at: "2026-09-02T00:00:00Z"
confirmed: false
side_effects: none
```

`source` has exactly the two origin kinds documented in
[source-contract.md](source-contract.md). `why`, objective, scope,
out-of-scope, and success criteria are the canonical boundary needed by the
plan family; decisions and unknowns preserve unresolved authority without
turning the packet into a workflow database. `confirmed: true` means the
restated intent is accepted by the responsible human or canonical Issue
contract; it is not inferred from silence. `--ready-for-plan` requires
confirmation, complete boundary fields, and no open questions. There is no
scenario/subskill or confidence-percentage requirement in this canonical
artifact.

For a non-trivial run, pair this packet with the root-owned `intent_run`
state generated by `intentctl`. The run state carries stage coverage, evidence
and claim IDs, trust/freshness signals, and the bounded session handoff; it does
not replace this human-readable intent packet or the canonical Issue/PLAN.
